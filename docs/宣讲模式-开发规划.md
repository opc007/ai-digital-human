# 宣讲带货模式（promo mode）· 开发规划

> 目标：在原项目基础上加一个**通用、可配置**的宣讲带货模式。
> 用户场景：教学/宣讲型直播（非娱乐），一边投产品官网、一边数字人出镜；
> 没人提问时自动宣讲，有人提问立即按知识库解答。
> 任何人下载后，替换 `knowledge/` + 改几行配置，就能推自己的产品。

---

## 一、开发思路（架构决策）

1. **原链路不动**：LLM 对答 → TTS 配音 → 嘴型合成 → 视频推流，全部保留。
   明确不做的：舞蹈/动作等娱乐互动生成、纯声音模式（用户已砍掉）。
2. **叠加层而非分支**：宣讲模式是可选叠加层，`promo.enabled=false`（默认）时行为与原来一字不差，
   保证零回归。
3. **三个新增能力**：
   - **知识库问答**：`knowledge/` 下的 `.md/.txt` 即知识库；启动时加载分段，
     提问时做本地中文 bigram 关键词检索（top-k），注入 system prompt。零依赖、不用向量库，
     通用且可替换。
   - **闲时自动宣讲**：队列空闲超过 `idle_seconds`（默认 45s），从 `promo_script.md`
     轮播一条原文播报；真人提问时**打断**当前宣讲、立即回答（`interrupt()` + 优先级）。
   - **网站分屏**：左网站、右人物。网站画面 = 开播时 headless 截图
     （playwright → chromium → 品牌占位图，三级降级）；后台线程定时刷新，
     仅在 idle 时热切换，不打断正在播的回复。说话片段 = 口型成片与网站图 xstack 合成。
4. **配置分层**：`configs/default.yaml` 的 `promo` 节（全局默认）+
   房间 yaml 的 `promo` 节（逐项覆盖，`None` 即用全局）。

## 二、具体开发细节（文件级）

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/engines/knowledge.py` | 新增 | `KnowledgeBase`：`load()` 扫描 md/txt（`promo_script.md` 不进检索）；`_split_chunks` 按空行/标题切段（≤500字）；`search()` bigram 打分 + 标题加权；`format_context()` 拼 prompt；`promo_lines()` 读宣讲稿 |
| `src/broadcast/compose.py` | 新增 | `capture_website()` 三级降级截图；`make_website_placeholder()` PIL 品牌占位图；`compose_split(left, right, ...)` ffmpeg xstack 左右分屏，`use_second_audio=True` 时沿用口型成片自带 TTS 音轨 |
| `src/broadcast/config.py` | 修改 | 新增 `RoomPromo`（全字段 Optional pydantic）；`RoomConfig` 加 `promo` 字段；`load_room_config()` 解析 |
| `configs/default.yaml` | 修改 | 新增 `promo` 节：`enabled/layout/knowledge_dir/promo_script/idle_seconds/product_name/website_url/website_title/website_refresh_sec/kb_top_k` |
| `configs/rooms/promo.yaml` | 新增 | 示例房间：AI电影梦宣讲间（persona=梦梦，`layout: split`） |
| `knowledge/ai-dian-ying-meng.md` | 新增 | 示例知识库（简介/用户/价格/功能/FAQ） |
| `knowledge/promo_script.md` | 新增 | 示例宣讲稿 7 条（`#` 开头为注释） |
| `src/orchestrator/live.py` | 修改 | `__init__` 合并全局+房间 promo 配置、加载 KB；`start()` 分屏 idle 底 + 启动网站刷新线程；`enqueue()` 真人提问打断宣讲；`_allow_user()` 放行 `promo`；`_run_interactive_loop()` 空闲分支调 `_maybe_promo()`；`_handle_one()` 开场白只播一次 + `promo` 原文播报 + `_promo_speaking` 标记；`_llm_reply()` 注入 KB 上下文；`_synth_and_lipsync()` 分屏合成说话片段；新增 `_capture_website/_compose_idle/_start_website_refresher/_maybe_promo` |
| `scripts/13_promo_setup.py` | 新增 | 一键配置 + 冒烟：`--room promo` 生成物料；`--smoke` 再跑 KB 检索/分屏合成/mock 全链路（greeting→闲时宣讲→提问打断→回答） |
| `README.md` | 修改 | 追加"宣讲带货模式"章节 |

关键并发语义：
- `_maybe_promo()` 只在队列 `Empty` 且 `state==IDLE` 时触发；宣讲条目 `priority=5`（低于真人默认 10）。
- 真人提问 `enqueue()` 时若 `_promo_speaking` 为真，先 `interrupt()`（清队列+切回 idle）再入队，保证"马上解答"。
- 网站刷新线程只在 `StreamManager.phase==IDLE` 时热切换 idle 底。

## 三、MiniMax 任务（按 5 小时算力窗口切分）

- **P0 了解（约 0.5h）**：读本 issue + 本规划文档；拉 `promo-mode` 分支，
  跑 `python scripts/13_promo_setup.py --room promo --smoke`（无 Key 可跑）。
- **P1 验收（约 1h）**：逐项对照第四节验收标准验证，问题记到本 issue。
- **P2 补齐修复（约 2h）**：修 P1 发现的问题；重点：有 Key 时 KB 回答是否引用原文、
  `website_only` 布局、控制台 `/api/v1/live` 状态是否需要暴露 promo 字段（可选）。
- **P3 推送（约 0.5h）**：合入 `main` 或开 PR；在本 issue 回复验收结论 + 测试证据。

## 四、验收标准

- [ ] 无 Key：`13_promo_setup.py --room promo --smoke` 全绿
- [ ] 有 Key 时：提问命中知识库，回答引用知识库原文信息（功能名/价格），不编造
- [ ] 闲时超 `idle_seconds` 自动宣讲；真人提问打断宣讲并立即回答
- [ ] 分屏成片：左网站右人物，音画同步；idle 底循环正常
- [ ] `demo` 房间（promo 关闭）行为与原来一致，零回归
- [ ] 换一套 `knowledge/`（删掉示例、放自己的 md），问答/宣讲自动跟随新内容

## 五、明确不做（已与用户确认砍掉）

纯声音输出模式、舞蹈/动作互动生成、控制台可视化配置抽屉（roadmap）。
