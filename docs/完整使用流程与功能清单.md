# 完整使用流程与功能清单

> 目的：先想清楚「用户从零到开播」要走哪些路，再反推每一步需要什么功能，避免东一块西一块。  
> 原则：**主路径 6 步能走完 = 产品可用**；支线能力后补。

---

## 一、用户是谁、最终要完成什么

| 角色 | 目标 |
|------|------|
| 个人主播 / 运营 | 用一张脸 + 一个声音 + 人设，推到抖音/快手等直播 |
| 技术向用户 | 可接本地 ComfyUI / Ollama，少花云费用 |
| 平台方（我们） | 配置简单、能预览、能真推、能排错 |

**成功标准（用户视角）：**

1. 我知道先干什么、后干什么（不迷路）  
2. 没有素材时能**上传或生成**  
3. 没有 Key 时能**先预览**，有 Key 后能**真说话**  
4. 能选平台、贴推流码、一键开播  
5. 直播中能**喂弹幕/话术**，数字人会回  
6. 出问题能看到**哪一步挂了**

## 二、主路径：6 步闭环（必须串起来）

```text
┌─────────────────────────────────────────────────────────────┐
│  Step 0  准备环境（装好本软件 / 打开控制台）                    │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1  准备形象素材                                         │
│  · 上传正脸图                                                 │
│  · 准备动作视频（上传 或 ComfyUI 生成）                        │
│  · 至少有 idle + 2～3 个说话动作                              │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2  准备声音                                             │
│  · 选云端 TTS / 本地 TTS                                      │
│  · 填 Key 或确认本地可用                                      │
│  · 试听一句，确认能出声                                       │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3  准备人设与对话脑                                     │
│  · 写开场白、人设提示词                                       │
│  · 选云端 LLM / 本地 Ollama                                   │
│  · （可选）测一句对话                                         │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4  选平台并配置推流                                     │
│  · 抖音/快手/视频号/小红书/仅预览                             │
│  · 粘贴推流码（预览可跳过）                                   │
│  · 看懂「如何拿推流码」说明                                   │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 5  开播前检查清单 → 一键开播                            │
│  · 素材齐？声音通？对话通？推流码？（预览可免）                 │
│  · 开始直播 / 预览                                            │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 6  直播中运营                                           │
│  · 状态可见（思考中/说话中）                                  │
│  · 手动输入弹幕、礼物优先、打断                               │
│  · 关播、资源释放                                             │
└─────────────────────────────────────────────────────────────┘
```

**分支（可后做，但要在地图上标出来）：**

- 6b 自动弹幕接入（官方 API / OCR，不做逆向）  
- 6c 多平台同播  
- 5b 真 RTMP 稳定性（断线重连已有基础）  
- 1b 形象一键批量生成 20 动作  
- 2b 声音克隆训练

## 三、每一步：要什么功能、验收标准、当前状态

### Step 0 — 进入产品

| 需要的功能 | 验收 | 现状 |
|------------|------|------|
| 启动服务一条命令 | `python scripts/07_run_api.py` 能开 | ✅ |
| 首页即「开播向导」 | 打开 8000 知道怎么走 | ✅ 三步向导 |
| 全局导航：开播 / 素材 / 配置 | 三处互相跳转 | ⚠️ 有链接，未做成统一顶栏流程条 |
| 环境自检结果进界面 | FFmpeg/GPU/素材是否就绪 | ⚠️ 分散在配置页，无「总检查」 |

**应补：** 首页顶部「当前进度：素材 → 声音 → 人设 → 推流 → 开播」可点击跳转；一键「开播前检查」。

---

### Step 1 — 形象素材

| 需要的功能 | 验收 | 现状 |
|------------|------|------|
| 上传正脸图 | 保存并预览 | ✅ 素材中心 |
| 上传动作视频（按动作名） | idle/wave/… 可替换 | ✅ |
| 动作列表与预览/删除 | 看得见缺什么 | ✅ |
| 本地 ComfyUI 地址配置 | 可保存、可测连通 | ✅ |
| 工作流说明 + 生成任务 | 有工作流可排队生成 | ✅ 框架有，依赖用户放 workflow |
| 无工作流时明确引导上传 | 不报错死胡同 | ✅ 文案有 |
| **素材是否满足开播的门槛提示** | 缺 idle 时禁止/警告开播 | ❌ 未强制 |
| 生成进度回写到动作列表 | 完成后自动出现视频 | ⚠️ 需手动刷新（有轮询但不统一） |

**应补：** 开播前检查「idle 必须存在」；生成完成后自动刷新素材状态。

---

### Step 2 — 声音

| 需要的功能 | 验收 | 现状 |
|------------|------|------|
| 云端 TTS Key 配置（可表单填） | MiniMax 等 | ✅ 云端配置 |
| 试听 TTS | 一句话出音频 | ✅ 素材中心 |
| 本地 TTS 路径 | local / edge-tts | ⚠️ 有，体验弱 |
| 上传参考音频 | 存盘 | ✅ 存了，未真正克隆 |
| **声音方案选择（云端音色 / 本地 / 样本）** | 开播时用哪套很清楚 | ❌ 未做成开播前一步 |
| 试听失败时的可读错误 | 缺 Key / 网络 | ⚠️ 半有 |

**应补：** 开播流程中增加「声音已就绪」状态；试听通过才算 Step2 完成。

### Step 3 — 人设与对话

| 需要的功能 | 验收 | 现状 |
|------------|------|------|

**应补：** 「试聊」按钮（只 LLM，不推流、不口型），降低试错成本。

## 四、信息架构（页面该怎么摆）

不要做成「工程师工具箱」，而要做成「向导 + 车间」：

```text
【开播控制台 /】          ← 主路径：平台 → 推流 → 算力 → 开播
     │
     ├─ 云端配置（抽屉）  ← Key、ComfyUI 地址、Ollama、音色
     │
     └─ 素材中心 /materials  ← 车间：形象/动作/生视频/声音试听
              │
              └─ 仍可回开播台
```

**理想顶栏（统一）：**

`开播` | `素材` | `配置` | 状态灯（素材✓ 声音✓ 对话✓）

## 五、按流程反推的「开发包」（功能模块地图）

| 流程步骤 | 功能包（模块） | 接口/界面落点 |
|----------|----------------|---------------|
| 1 形象 | 素材库 CRUD、预览、门槛 | `/materials` + `/api/v1/assets*` |
| 1 生成 | ComfyUI 客户端、任务队列、工作流 | `/api/v1/comfyui*` `/api/v1/assets/generate` |
| 2 声音 | TTS 引擎、试听、样本、音色配置 | `/api/v1/voice*` + 云端配置 |

| 3 脑 | LLM 工厂 cloud/local | engines/llm |
| 4 平台 | 平台预设、推流码、说明 | platforms.yaml + 开播向导 |

| 6 互动 | 队列、审核、WS、优先级 | orchestrator + ws |
| 全局 | 设置存储 .env、健康检查 | settings_store、bootstrap |

## 六、推荐实现顺序（严格按主路径堵点）

### P0 — 没有就不能叫「能用」（优先）

1. **开播前检查 preflight**（素材 idle、FFmpeg、预览/推流码、可选 LLM/TTS 状态）  
2. **统一顶栏导航 + 进度条**（用户永远知道自己在第几步）  
3. **试聊（只文本）** + **试听已有** 串到检查清单  
4. 缺素材时开播按钮降级：只允许「仅预览」或直接引导去素材中心  

### P1 — 主路径体验变顺

5. 素材生成完成自动刷新  
6. 声音方案在开播第三步明示「当前用 MiniMax / 本地 / 演示」  
7. 错误文案统一成人话（缺 Key / Comfy 离线 / 无 idle）  

### P2 — 增强

8. 真 MuseTalk、声音克隆、自动弹幕、多平台同播、计费

## 七、一条「标准演示脚本」（验收用）

任何人按这个走通 = 流程合格：

1. 打开 `/` → 点「素材中心」  
2. 上传一张正脸（或跳过若已有动作）  
3. 确认 idle 等动作存在（上传或占位）  
4. 声音：试听一句（无 Key 则演示音也要有反馈）  
5. 回 `/` → 云端配置（可选填 Key）→ 人设改开场白  
6. 平台选「仅预览」→ 云端模式 → 开始直播  
7. 输入「你好」→ 看到回复与状态变化  
8. 结束直播  

真推流再加：选抖音 → 贴推流码 → 开始 → 伴侣见画面。

---

## 八、结论（给开发的一句话）

> **先保证「6 步主路径」每一步有入口、有状态、有失败提示，再加深某一技术点（口型/弹幕/集群）。**  
> 缺的不是更多微服务，而是：**流程导航 + 开播前检查 + 试聊试听闭环**。
